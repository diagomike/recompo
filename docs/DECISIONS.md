# Decisions

D-01 … D-16 were agreed on 2026-10-15 and are listed in [PLAN.md §1](PLAN.md#1-decisions-agreed-in-conversation-2026-10-15).
Decisions taken during the build are appended here.

| # | Date | Decision | Why |
|---|---|---|---|
| D-17 | 2026-10-15 | Short refs (`S1`, `S1.c4`, `C17`, `J2#3`) are allocated per kind from a `refseq` table and never reused. | Refs are how the user and agent talk about things in chat; a reused ref would point at the wrong thing in an old message. |
| D-18 | 2026-10-15 | Undo works at row level (each op stores before/after rows). Undo refuses if a row changed since (E_CONFLICT), and refuses to undo a higher-precedence actor's op. Bulk machine data (segments, words, shots) is not op-logged. | A generic, verifiable inverse for every verb, without hand-written inverse functions. |
| D-19 | 2026-10-15 | CLI positionals are optional at the argparse level; pydantic reports missing fields. All CLI failures, including usage errors, print a JSON envelope. | Agents always get parseable output and a hint. |
| D-20 | 2026-10-15 | The viewer learns about changes by tailing the `event` table (SSE in the studio server polls it). | The CLI, the MCP server and jobs are separate processes; the database is the one place they all write. |
| D-21 | 2026-10-15 | `recomp` launchers go in `~/bin` (on Git Bash's PATH), via `recomp setup shim`; Windows PATH is not modified. | Agents in any project folder can call `recomp` without touching system settings. |
| D-22 | 2026-10-16 | **The research wing is for an active creation team, not a passive observer of trends.** It finds and follows the creators you love and makes journeys from their new posts and from topics in the air (news, or what you name) that several of them have opinions on, now or in the past. Trend sources are prompts for topics; no market ranking, no studying other clippers, no "post what performs". | Your direction on 2026-10-16. Market-watching (replay heatmaps, other clippers' uploads, view outliers, backtests) was copyright-heavy and not the point; the product is opinion-led journeys around people you follow. |
| D-23 | 2026-10-16 | **Rights model** (replaces every earlier rights rule in PLAN.md and the research note). Each source is `campaign` (a clipping program covering it is running, terms linked), `permitted` (creator's permission verified, evidence linked) or `private`. Only `campaign`/`permitted` sources can enter the posting queue, enforced in the verb; every post credits the creator (D-09). `private` sources have no other limits. Recipes are private by default; publishing one on the hub is always allowed after a confirmation that lists each source's status, states what changes for each `private` source (public page, plays to strangers via the official embed, your name next to the creator's) and asks "Do you have permission to share this?". `hub publish` from CLI/MCP stops and returns the same until you pass `--confirm`; the agent cannot answer for you; the answer and time are saved on the recipe version. You upload (D-10); reading your own channel's analytics (read-only access or a Studio CSV) is allowed. | Your rights model of 2026-10-16: full freedom for private work, a hard gate only where content leaves for an audience, and a human answer on record. |
| D-24 | 2026-10-16 | **yt-dlp may use your browser cookies** for the research wing (`network.cookies_from_browser`, or a `network.cookies_file` export). Published transcripts and feeds come first; cookies only when YouTube blocks. | Your permission on 2026-10-16. Chrome locks its cookie database while open, so an exported cookies.txt is the practical route. |
